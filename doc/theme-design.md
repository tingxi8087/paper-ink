# 主题体系设计草案

记录日期：2026-10-10

状态：主题设计方向已认可；变量名称、完整清单和派生细节仍需在实现前细化。本文示例不是已发布的 API。

## 目标

组件 API 保持 Ant Design 的使用习惯，主题体系独立设计。用户应能明确知道：

1. 修改整套风格在哪里配置。
2. 修改某种视觉用途会影响哪些地方。
3. 只修改一个组件在哪里配置。

默认黑白灰主色，其他语义色参考 Ant Design。减少难以理解的命名和隐式派生，保留全局定制、组件定制及后续扩展能力。

## 分层

| 层级 | 责任 | 示例 |
| --- | --- | --- |
| 基础尺度 | 提供原始色板、间距和字号尺度，主要用于维护主题 | 灰阶、间距序列 |
| 全局语义 | 根据用途命名，供组件和业务页面共用，是日常定制的主要入口 | 正文、容器、边框、主操作 |
| 组件配置 | 调整某个组件特有的视觉细节 | Button 横向内边距、圆角 |

组件样式优先消费语义变量，不直接绑定某个原始灰阶值，以便支持品牌换色和暗色主题。

## 命名和结构

采用按用途分组的嵌套结构，颜色按“用途 + 状态”命名。下面仅展示部分变量：

```ts
const token = {
  color: {
    text: {
      primary: '#171717',
      secondary: '#737373',
      disabled: '#a3a3a3',
    },
    surface: {
      page: '#ffffff',
      container: '#ffffff',
      elevated: '#ffffff',
      muted: '#f5f5f5',
    },
    border: {
      default: '#d4d4d4',
      subtle: '#e5e5e5',
    },
    primary: {
      solid: '#171717',
      solidHover: '#404040',
      solidActive: '#262626',
      onSolid: '#ffffff',
      subtle: '#f5f5f5',
      onSubtle: '#171717',
      border: '#a3a3a3',
    },
    // success / warning / error / info 使用相同的角色结构。
  },
}
```

- `solid` 表示实心背景，`onSolid` 表示该背景上的文字或图标。
- `subtle` 表示浅色背景，`onSubtle` 表示该背景上的文字或图标。
- 背景与前景成对设计，避免品牌换色后前景仍使用不适合的颜色。
- 交互状态直接使用 `Hover`、`Active` 等名称，不要求使用者理解色阶编号。
- 按实际需求增加状态变量，不预先穷举所有用途和状态组合。
- 全局语义变量同时服务组件库和业务页面，含义不能依赖单个组件的实现。

示例色值用于说明结构，尚未完成视觉和对比度验收。

## 覆盖与派生

默认值可以有关联，但关联规则必须集中、明确且可预测。

- 修改主色时，可以生成默认的 hover、active、浅色背景等相关值。
- 用户明确配置的值始终优先于自动派生值。
- 派生集中在主题处理模块，组件内部不另外计算颜色。
- 黑白主色需要专门考虑，不能直接套用彩色加深逻辑。
- 同一个视觉属性的取值顺序固定为：组件显式覆盖 → 全局语义变量 → 内置默认值。
- 组件变量保持少量，命名尽量继承全局语义。

派生算法、输入格式、前景色选择，以及局部主题中的继承和重新派生顺序尚待确定。

## 配置入口草案

保留熟悉的 `ConfigProvider`、`theme.token`、`theme.components` 形态，内部变量结构重新设计。

```tsx
<ConfigProvider
  theme={{
    token: {
      radius: { control: 6 },
      color: {
        primary: {
          solid: '#171717',
          onSolid: '#ffffff',
        },
      },
    },
    components: {
      Button: {
        radius: 999,
        paddingInline: 16,
      },
    },
  }}
>
  <App />
</ConfigProvider>
```

JS 变量与 CSS 变量一一对应，例如：

```text
color.text.primary → --pi-color-text-primary
color.primary.solidHover → --pi-color-primary-solid-hover
```

让配置、文档和浏览器调试中的名称可以直接对应。CSS 变量的作用域及弹层继承方式需在实现前明确。

## 尺寸与其他变量

- 控件高度、字号、间距、圆角分别配置，不全部绑定在一个基础值上。
- 调整字号不应隐式改变整套控件高度或弹窗间距。
- 紧凑模式可以是一组明确的预设。
- 阴影、焦点环、动效及浮层层级按真实需求加入，避免过早暴露大量变量。

布局间距已实现为 `theme.token.spacing`：`small=4`、`medium=8`、`large=16`（单位 px）。Stack、Inline、SimpleGrid 默认使用 medium；预设继承主题，显式数字及 CSS 字符串不受预设覆盖。

## 当前实现进度

已实现分组的主题类型、默认语义色、显式深层覆盖、嵌套继承、`inherit: false`、CSS 变量映射，以及 Button 的圆角和横向内边距覆盖。文档站提供主题实验室。

自动颜色派生、暗色预设、直接 CSS 覆盖策略和弹层主题作用域仍是后续事项；当前修改颜色不会自动改变相关状态色。

- 确定明暗主题及颜色派生方案。
- 确定数字、单位和 CSS 值的输入规则。
